## 방장이 원한 것 (원문 요약)

1. 채팅방 best practice 설계. 복잡하지 않고 간결하게 핵심만.
2. AI는 말만 걸면 무조건 답한다. 그러지 않게 하고 싶다.
   사람 채팅은 생각도 하고, 누가 먼저 답하면 쓰다 지우고, 답한 게 맘에 안 들어 반박하고,
   남이 쓰는 걸 기다리고, 쓰다 멈추고 다시 쓴다. 가능한 모든 경우를 설계에 반영할 것.
   실시간성이 중요하지만 AI 특성상 어느 정도 느린 건 감당한다.
3. 각 AI는 자기 토큰 사용량을 항상 주시. 특정 미만이면 **입력 자체도 안 받아야 한다**.
4. 방장으로서 각 서비스의 model과 추론 깊이를 설정할 수 있어야 한다.
5. 모두 내 구독이 아닐 수 있다. 타인 것은 오로지 채팅만. 내가 임의로 토큰을 소모시키는 걸 방어할 것.
6. 빠진 설계가 있으면 간결하게 정리해서 보고할 것.

2차 요구:

- TUI 우선. "나"는 휴대폰 앱으로 접속할 수도 있음.
- MCP 활용 가능한지 답할 것.
- **침묵도 입력이다.** 침묵 속에서 스스로 대답할 줄 알아야 한다.
  n턴 설정 가능하게 하고, 몇 턴 지나면 CLI나 OS 알림, 휴대폰으로도 알림이 가면 좋겠다.
- DB 필요한지 고려할 것.
- 장애 격리 필요.
- 1턴만 지나도 컨텍스트가 바뀌는데 느린 모델 대답 기준으로 속도를 맞춰야 하나?
- 성격 부여 기능 필요.
- 일단 codex와 claude만 쓰면 된다. **테스트할 때는 둘 다 가장 값싼 모델로.**

## 결정과 그 이유

### 채택

| 결정 | 이유 |
|---|---|
| Headless JSON 스트림 | 토큰 사용량과 타이핑 상태를 구조화된 값으로 읽는다. 방장이 커맨드를 칠 일은 없고 서버가 대신 실행한다 |
| 의향 타진 후 발언 (2단계) | 넷이 동시에 전체 답변을 만들면 셋은 버려지고 토큰만 탄다. 의향 없음이 곧 자연스러운 침묵이 된다 |
| 발언권 창 + 맥락 앵커 | 전체 속도를 느린 모델에 맞추면 모두가 최저 속도로 떨어진다. 발언권을 딴 사람에게만 기다려준다 |
| 침묵을 1급 이벤트로 | 침묵 방송이 의향 타진의 방아쇠가 된다. 자동 휴면 타이머가 짝을 이뤄 토큰 증발을 막는다 |
| 텔레그램 봇 브리지 | 알림과 모바일 접속이 한 번에 해결된다. 앱 개발 불필요, 서버 공개 불필요, 그 자리에서 답장 가능 |
| 방어선을 소유자 쪽에 | 게스트 데몬이 자체 상한을 들고 방 서버 요청을 거절할 수 있다. 서버를 신뢰하지 않아도 안전하다 |
| 예산 2겹 (서버 계산 + CLI 자체 상한) | `claude --max-budget-usd` 가 있다. 서버에 버그가 있어도 2차가 남는다 |
| JSONL 로그, DB 없음 | 쓰기는 전부 덧붙이기, 읽기는 최근 대화와 전체 재생뿐 |
| TUI 1급, 웹은 얇은 뷰 | 방장의 주 사용 환경이 터미널이다 |

### 기각

| 기각한 것 | 이유 |
|---|---|
| PTY로 실제 CLI 화면 조작 | 색상 코드와 커서 이동이 섞인 화면 파싱은 자주 깨지고 CLI 업데이트마다 다시 깨진다. 토큰 수치도 화면에서 긁어야 해 부정확하다 |
| 참여 AI가 MCP로 방을 폴링해 스스로 끼어들기 | headless 턴은 끝나면 프로세스가 죽어 지속 폴링이 불가능하다. 폴링 자체가 토큰을 태운다. 침묵은 서버가 밀어주는 게 훨씬 싸다 |
| 배리어 동기화 (모두 응답할 때까지 대기) | 모두가 가장 느린 참여자 속도로 떨어진다. 사람 대화와도 다르다 |
| 지금 DB 도입 | 과설계. 이벤트 로그가 진실의 원천이면 나중에 언제든 재구축할 수 있다 |
| 저장 계층 추상화 인터페이스 | 같은 이유. 로그만 잘 남기면 된다 |

### 설계 과정에서 방장이 언급하지 않았으나 추가한 것

1. 맥락 주입 시 타 참여자 발언을 인용 데이터로 감싸기 (프롬프트 인젝션 차단)
2. 자동 휴면 (AI끼리 무한 맞장구로 밤새 토큰이 증발하는 것 방지)
3. 취소된 발언이 태운 토큰을 낭비 항목으로 별도 기록 (선점 정책 조정 근거)
4. 느린 참여자 형평 보정 (연속 3회 기회를 놓치면 다음 라운드 지연 0)
5. 지각 발언 판정 (3턴 이상 밀리면 폐기)
6. 성격 수치화 (문구만으로는 대화 리듬이 안 바뀐다)
