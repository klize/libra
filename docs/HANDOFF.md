# Libra 세션 이관 메모

수정일: 2026-09-14. 구현 전.
설계 기준은 [설계 명세](superpowers/specs/2026-09-14-libra-design.md)다.

## 사용자가 정한 방향

- 사람과 여러 AI가 자연스럽게 대화하는 채팅방. 설계는 간단명료하게 쓴다.
- 채팅에 한 명만 갖는 발언권은 없다. 여러 참여자가 동시에 쓰고 답할 수 있다.
- 새 말이 왔다고 무조건 취소하지 않는다. 계속 쓰거나, 고치거나, 그만둘 수 있다.
- 턴은 누군가의 발화에 다른 누군가가 답한 교환이다. 내부 모델 호출과 구분한다.
- 사용량은 조회해서 쓰고, 미확인이면 표시한다. 실제 리밋이 걸리면 해당 참여자가 쉰다.
- 게스트 소유자의 제한은 방장이 우회할 수 없어야 한다.
- 프로젝트 이름은 Libra로 확정했다.

## 유지하는 결정

TypeScript + Node, Ink TUI 우선, 구조화된 JSON 입출력, JSONL 기록.
초기 참여자는 Claude와 Codex. 테스트는 haiku·luna 계열의 최저가 모델로 한다.
모델·추론 깊이·성격 설정, 침묵에서 먼저 말하기, 알림·Telegram·웹·MCP 연결을 제공한다.
게스트는 소유자 PC의 데몬에서 대화만 하며 자격 증명과 제한 정책을 관리한다.
당장 DB나 저장 추상화 계층은 만들지 않는다.

## 이번에 바꾼 설계

공유 대화 기록과 참여자별 세션·받은 메시지 목록을 둔다.
참여자는 독립적으로 응답하고, 같은 세션의 실행만 겹치지 않게 한다.
필수 의향 타진, 단일 발언권, 새 메시지마다 자동 취소, 메시지 수에 따른 답변 폐기를 없앴다.
반응 지연 수치로 자연스러움을 보장한다는 가정도 두지 않는다.

가만히 기다릴 때 모델을 호출하지 않는다. 침묵 깨우기는 별도 이벤트다.
전원이 응답하지 않으면 같은 침묵으로 계속 호출하지 않는다.
사용량 조회 실패를 복잡한 비용 정산 설계로 확대하지 않는다.

## 다음 작업

두 CLI의 응답 생략·실행 중 입력·취소·재개·사용량·리밋 동작을 먼저 확인한다.
최소 대화에서 동시 응답, 중간 메시지, 침묵, 제한 처리를 검증하고 세부 정책을 정한다.
OpenClaw의 참고 구조는 설계 명세 마지막에 링크했다. 실제 대화 품질은 아직 미검증이다.
