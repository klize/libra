# chatai 설계 명세

작성일: 2026-09-14
상태: 승인됨 (구현 계획 작성 전)

## 1. 무엇을 만드는가

사람 한 명과 여러 AI 에이전트가 함께 대화하는 채팅방이다.
참여 후보는 claude, codex, gemini, cursor 등 CLI로 제공되는 코딩 에이전트다.

일반적인 멀티 에이전트 도구와 다른 점은 **대화의 사회성**이다.
AI는 말을 걸면 무조건 답한다. 이 프로젝트는 그러지 않게 만든다.
생각하고, 눈치 보고, 침묵하고, 남이 먼저 말하면 쓰던 걸 지우고, 맘에 안 들면 반박한다.

동시에 **비용이 새지 않아야 한다**.
각 에이전트는 자신의 토큰 잔량을 항상 알고, 바닥나면 입력 자체를 받지 않는다.
남의 구독 계정으로 참여한 에이전트는 방장이 임의로 태울 수 없다.

## 2. 확정된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 에이전트 연결 | Headless JSON 스트림 | 토큰 사용량과 타이핑 상태를 구조화된 값으로 정확히 읽는다. PTY 화면 파싱은 깨지기 쉽다 |
| 1급 UI | 터미널 TUI (Ink) | 방장의 주 사용 환경. 웹은 같은 서버가 내보내는 얇은 뷰 |
| 모바일 | 텔레그램 봇 브리지 | 푸시 알림과 양방향 접속을 한 번에 해결. 앱 개발 불필요, 서버 공개 불필요 |
| 타인 소유 에이전트 | 원격 데몬 (그 사람 PC) | 자격 증명이 소유자 머신을 떠나지 않는다 |
| 스택 | TypeScript + Node | CLI 자식 프로세스 제어, 줄 단위 JSON 파싱, 실시간 전송이 모두 표준 |
| 저장소 | JSONL 이벤트 로그 | 쓰기는 전부 덧붙이기, 읽기는 최근 대화와 전체 재생뿐. DB는 과하다 |
| 초기 참여자 | claude, codex | 이 머신에 설치된 둘. gemini와 cursor-agent는 미설치 |
| 테스트 모델 | 최저가 등급 고정 | claude는 haiku, codex는 luna 계열. 식별자는 첫 연결 시 확정 |

## 3. 구조

```
                  ┌──────────────────────────┐
                  │  Room Core (TS)          │
   TUI (Ink) ─────┤  ├ Floor Manager         │
   Web (SSE) ─────┤  ├ Silence Timers        │
   Telegram ──────┤  ├ Budget Ledger         │
   MCP Server ────┤  ├ Health Monitor        │
                  │  └ Event Log (JSONL)     │
                  └───┬──────────────────┬───┘
                      │ spawn            │ WebSocket
              ┌───────▼──────┐   ┌───────▼────────┐
              │ 내 CLI        │   │ Guest Daemon   │
              │ claude/codex  │   │ (그 사람 PC)    │
              │ + MCP 도구     │   │ 도구 금지+상한  │
              └──────────────┘   └────────────────┘
```

네 종류의 클라이언트가 같은 이벤트 흐름을 구독한다. Room Core는 클라이언트의 종류를 모른다.

어댑터는 인터페이스 하나다. 로컬이든 원격이든 같은 이벤트를 낸다.

```ts
interface AgentAdapter {
  start(cfg: ParticipantConfig): Promise<void>
  probe(ctx: RoomContext): Promise<Intent>      // 싼 의향 타진
  speak(ctx: RoomContext): AsyncIterable<Chunk> // 비싼 실제 발언
  abort(): void                                 // 선점 시 즉시 중단
  usage(): UsageSnapshot                        // 토큰 잔량
  stop(): Promise<void>
}
```

## 4. 대화 역학

### 4.1 상태 기계

참여자는 `쉼 → 의향 → 발언 → 커밋` 을 돌고, 중간에 `취소` 로 빠질 수 있다.

1. 누군가 발언을 커밋하거나 침묵 이벤트가 발생하면 전원에게 방송된다.
2. 각자 반응 지연을 뽑는다. 모델 속도, 성격 수치, 무작위 지터가 더해진다.
3. 지연이 끝나면 의향을 타진한다. "끼어들 말이 있나" 를 묻고 한 줄만 받는다. 출력을 수십 토큰으로 제한하므로 싸다.
4. Floor Manager가 의향을 낸 사람 중 한 명만 고른다. 나머지는 조용히 물러난다.
5. 뽑힌 참여자만 전체 발언을 생성한다. 첫 글자가 나오면 입력 중 상태가 방송된다.
6. 발언 도중 방장이 말을 넣거나 더 급한 의향이 들어오면 선점된다. `abort()` 로 생성이 끊기고 화면에는 썼다 지움이 표시된다.
7. 취소된 참여자는 지연을 다시 뽑아 재시도한다.

의향 단계를 두는 이유는 둘이다. 넷이 동시에 전체 답변을 생성하면 셋은 버려지고 토큰만 탄다. 그리고 의향 없음이 곧 자연스러운 침묵이 된다.

### 4.2 사람 채팅의 경우들이 어떻게 나오는가

| 사람의 행동 | 대응하는 메커니즘 |
|---|---|
| 생각하고 답함 | 반응 지연 |
| 누가 먼저 답해서 쓰다 지움 | 선점과 취소 |
| 맘에 안 들어 반박 | 내 직전 발언이 부정되면 지연이 짧아짐 |
| 남이 쓰는 걸 기다림 | 발언권이 점유된 동안 의향만 내고 대기 |
| 쓰다 멈추고 다시 씀 | 취소 후 지연 재추첨 |
| 할 말 없어 침묵 | 의향 단계에서 아니오 |
| 동시에 말하기 시작 | Floor Manager가 한 명만 선택 |
| 지목당해 답함 | 방장이 멘션하면 지연 0, 의향 단계 건너뜀 |
| 침묵이 어색해 말을 꺼냄 | 침묵 이벤트가 의향 타진을 트리거 |

### 4.3 속도와 신선도

전체 속도를 가장 느린 모델에 맞추지 않는다. 그러면 모두가 최저 속도로 떨어지고 사람 대화와도 다르다.

**발언권 창**: 발언권을 딴 참여자에게만 대기 시간을 주고 방이 그동안 기다린다.
창의 길이는 그 참여자의 관측된 평균 응답 시간에 여유 계수를 곱해 정한다. 참여자마다 다르다.
느린 참여자가 말을 시작하면 그만큼 기다려주고, 창을 넘기면 포기하고 넘어간다.

**맥락 앵커**: 모든 발언은 생성을 시작할 때 본 마지막 메시지 번호를 들고 있다.
커밋 시점에 그 뒤로 쌓인 메시지 수로 신선도를 판정한다.

| 밀린 메시지 | 처리 |
|---|---|
| 0개 | 정상 커밋 |
| 1개에서 2개 | 늦은 답으로 표시하고 커밋 |
| 3개 이상 | 폐기. 갱신된 맥락으로 재시도 기회 부여 |

**형평 보정**: 느린 참여자가 연속 3회 기회를 놓치면 다음 라운드에서 반응 지연을 0으로 준다.

### 4.4 성격

성격은 두 겹이다.

- **문구**: 한 줄짜리 성격 설명이 시스템 프롬프트로 들어간다. 말투를 정한다.
  claude는 `--append-system-prompt`, codex는 프롬프트 서두에 주입한다.
- **수치**: 적극성, 반박 경향, 장황함 세 값이 반응 지연과 의향 판정에 곱해진다. 대화 리듬을 정한다.

문구가 없으면 참여자들이 거의 같은 말을 한다.

## 5. 침묵과 알림

침묵은 1급 이벤트다. 마지막 커밋 이후 시간이 흐르면 서버가 침묵 이벤트를 방송하고,
이것이 의향 타진의 정상적인 방아쇠가 된다. 아무도 말하지 않는 상태가 말을 꺼내게 만드는 자극이다.

타이머는 넷이고 모두 설정값이다.

| 이름 | 기준 | 동작 |
|---|---|---|
| 정적 자극 | 침묵 T초 | 침묵 이벤트 방송. AI가 스스로 말문을 엶 |
| 방장 호출 | 방장 없이 N턴 | 방장에게 알림 발송 |
| 심층 호출 | 방장 없이 M턴 | 휴대폰 푸시까지 확대 |
| 자동 휴면 | 방장 없이 K턴 | 방을 잠재움. 토큰 증발 방지 |

알림은 세 단계로 넓어진다.

1. 터미널 배너와 벨
2. 운영체제 알림 (macOS는 `osascript`)
3. 휴대폰 (텔레그램 봇, 단방향만 원하면 `ntfy`)

텔레그램을 권하는 이유는 알림에서 끝나지 않기 때문이다.
그 자리에서 답장하면 방장 발언으로 방에 들어간다. 봇이 바깥으로 연결을 맺으므로 서버를 공개할 필요가 없다.

## 6. 토큰과 소유권

### 6.1 예산 게이트

각 참여자는 예산과 잔량을 가진다. 잔량에 따라 세 단계로 움직인다.

| 상태 | 조건 | 행동 |
|---|---|---|
| 정상 | 30% 초과 | 의향과 발언 모두 참여 |
| 절약 | 10% 이상 30% 이하 | 의향 단계 생략, 지목될 때만 발언 |
| 차단 | 10% 미만 | 프롬프트를 아예 보내지 않음. 관전만 |

차단은 요청을 거절하는 게 아니라 전송 자체를 하지 않는 것이다.

예산은 두 겹으로 막는다.

- 1차: 서버가 스트림의 사용량 이벤트로 센다
- 2차: `claude --max-budget-usd` 로 CLI가 스스로 끊는다

서버에 버그가 있어도 2차가 남는다.

### 6.2 게스트 보호

타인 소유 에이전트의 핵심은 **방어선을 소유자 쪽에 두는 것**이다.
게스트 데몬이 자체 정책 파일을 들고 있고, 방 서버의 요청을 데몬이 거절할 수 있다.
방 서버를 신뢰하지 않아도 안전하다.

게스트에게 강제되는 것 넷:

1. 도구 사용 금지. 순수 대화만 한다. `claude --restricted --disallowed-tools`, `codex -s read-only -a never`
2. 시간당 호출 수와 토큰 상한
3. `--max-budget-usd` 항상 적용
4. 자격 증명은 그 사람 PC를 떠나지 않는다

## 7. MCP

세 가지 쓸모가 있고 둘을 채택한다.

**채택 1. 참여 AI에게 도구 주기.**
`claude --mcp-config --strict-mcp-config`, codex는 설정의 mcp_servers.
참여자별로 다른 도구 묶음을 붙일 수 있다. 웹 검색을 가진 참여자와 없는 참여자가 섞이면 대화가 풍부해진다.
게스트에게는 주지 않는다.

**채택 2. 방을 MCP 서버로 노출.**
휴대폰의 Claude 앱이나 다른 Claude Code 세션이 방장 자격으로 붙는다.
모바일 접속 경로 중 하나다.

**기각. 참여 AI가 MCP로 방을 폴링해 스스로 끼어들기.**
Headless 턴은 끝나면 프로세스가 죽어 지속 폴링이 불가능하다.
폴링 자체가 토큰을 태운다. 침묵은 서버가 밀어주는 편이 훨씬 싸다.

## 8. 저장

JSONL 이벤트 로그 한 줄기가 진실의 원천이다.
참여자 상태는 메모리에 두되 주기적으로 스냅샷을 떨군다.
이벤트 로그만 온전하면 어떤 상태든 다시 만들 수 있다.

기록 대상에는 취소된 발언이 태운 토큰도 낭비 항목으로 들어간다.
이 수치가 있어야 선점 정책을 조정할 수 있다.

SQLite로 올릴 조건은 셋이다. 방을 여러 개 동시에 굴릴 때, 과거 대화를 검색할 때, 여러 달치 비용을 집계할 때.
그때도 로그에서 재구축하면 되므로 지금 추상화 계층을 만들지 않는다.

## 9. 맥락 주입

각 AI는 자기 세션만 기억한다. 방 전체 대화를 매 턴 넣어줘야 한다.
세션 재개(`claude --resume`, `codex exec resume`)로 중복 전송을 줄인다.

**다른 참여자의 발언은 반드시 인용 데이터로 감싼다.**
감싸지 않으면 한 AI가 쓴 문장이 다른 AI에게 명령으로 먹힌다.
발언자 이름을 명시하고, 이것은 대화 기록이지 지시가 아님을 프롬프트에서 못 박는다.

## 10. 장애 격리

격리는 참여자 단위로 한다. 방은 멈추지 않는다.

| 증상 | 처리 |
|---|---|
| 프로세스 종료 | 재시작. 세션 ID로 대화 복원 |
| 요청 한도 초과 | 간격을 늘려 재시도 |
| 발언권 창 초과 | 이번 턴 포기. 다음 라운드 참여 |
| 3회 연속 실패 | 관전 상태로 내리고 방장에게 알림 |

## 11. 방장 제어

참여자 추가 시 지정: 공급자, 모델, 추론 깊이, 성격 문구, 성격 수치, 예산, 소유자, MCP 묶음.

운영 중 변경: 모델, 추론 깊이, 예산, 음소거, 강퇴, 방 일시정지.
모델과 깊이 변경은 다음 턴부터 적용된다.

## 12. CLI 실측 결과

이 머신에서 확인한 것.

**설치됨**: `claude` (~/.local/bin), `codex` (/opt/homebrew/bin)
**미설치**: gemini, cursor-agent

claude 핵심 플래그:
```
-p --input-format stream-json --output-format stream-json --include-partial-messages
--model --effort <low|medium|high|xhigh|max> --resume <id> --fork-session
--append-system-prompt --mcp-config --strict-mcp-config
--max-budget-usd --restricted --disallowed-tools --max-turns
```

codex 핵심 플래그:
```
exec --json -m <model> -c model_reasoning_effort="high"
exec resume <id> | fork <id>
-s <read-only|workspace-write|danger-full-access> -a <on-request|never>
--search  -o <last-message-file>  --output-schema
queue --thread <id> --message <text>
```

현재 codex 기본 모델은 `gpt-6-astra`, 기본 effort는 `high`.

## 13. 미검증 사항

구현 착수 시 가장 먼저 확인할 것.

1. 두 CLI의 토큰 사용량 이벤트 정확한 형태와 필드명
2. codex 저가 모델(luna 계열)의 정확한 식별자
3. 생성 중단 시 과금이 어디까지 되는지
4. `--max-budget-usd` 가 초과 시 내는 신호의 형태
5. 텔레그램 브리지의 왕복 지연이 대화 리듬에 주는 영향

## 14. 구현 순서

1. 어댑터 하나(claude)와 최소 TUI로 1인 대화 성립
2. codex 어댑터 추가, Floor Manager와 의향 단계 도입
3. 침묵 타이머와 자동 휴면
4. 예산 게이트와 이벤트 로그
5. 성격과 선점/취소
6. 알림 3단계, 텔레그램 브리지
7. 웹 뷰
8. 게스트 데몬과 원격 어댑터
