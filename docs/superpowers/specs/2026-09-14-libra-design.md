# Libra 설계 명세

수정일: 2026-09-14
상태: 대화 방식 수정 반영. 구현 전, CLI 동작과 대화 품질은 미검증.

## 1. 무엇을 만드는가

사람과 여러 AI가 함께 대화하는 채팅방이다.
참여자는 답하거나, 기다리거나, 침묵할 수 있다. 여러 명이 동시에 작성하고 답할 수 있다.
새 말이 들어와도 쓰던 말을 계속하거나, 내용을 고치거나, 그만둘 수 있다.
성격과 맥락에 따라 이런 선택이 달라지는 대화를 만든다.

## 2. 기본 구성

| 항목 | 결정 |
|---|---|
| 초기 참여자 | Claude, Codex. 다른 CLI는 이후 추가 |
| 연결 | 구조화된 JSON 입출력을 쓰는 CLI 어댑터. 로컬과 원격에 같은 역할 제공 |
| 스택 | TypeScript + Node |
| 화면 | Ink TUI 우선. 웹은 같은 대화 기록을 보여주는 뷰 |
| 모바일 | Telegram으로 알림과 대화 참여 |
| 저장 | JSONL 이벤트 로그. 당장 DB나 저장 추상화 계층을 만들지 않음 |
| 게스트 | 소유자 PC의 데몬으로 연결. 자격 증명과 제한 정책은 소유자 쪽에 둠 |
| 테스트 | Claude는 haiku, Codex는 luna 계열의 최저가 모델. 정확한 식별자는 실행 전 확인 |

Room Core는 공유 대화 기록, 참여자별 받은 메시지 목록, 사용량·상태를 관리한다.
각 참여자는 자기 CLI 세션을 유지한다. 화면과 외부 연결은 같은 이벤트를 구독한다.

## 3. 대화 방식

1. 사람이나 AI가 보낸 메시지를 기록하고 다른 참여자에게 전달한다.
2. 각 참여자는 자기 세션에서 답할지 판단한다. 답변 없이 끝내는 것도 정상이다.
3. 여러 참여자가 동시에 작성할 수 있고, 답변은 도착하는 대로 게시한다.
4. 답변에는 어떤 메시지에 대한 답인지 연결한다. 늦게 왔다는 이유로 버리지 않는다.
5. 게시된 답변도 다른 참여자가 이어받을 수 있다. 모두 할 말이 없으면 대화가 멈춘다.

같은 참여자의 세션에는 실행을 겹쳐 시작하지 않는다. 실행 중 들어온 메시지는 모아 둔다.
참여자끼리는 서로의 실행이 끝나기를 기다릴 필요가 없다.

### 작성 중 새 메시지가 왔을 때

| 선택 | 동작 |
|---|---|
| 계속 쓰기 | 현재 답을 마친 뒤 새 메시지를 확인 |
| 고쳐 쓰기 | CLI가 지원하는 시점에 새 내용을 받아 답에 반영 |
| 그만두기 | 현재 초안을 중단하고 기다리거나 새 내용으로 다시 작성 |

새 메시지 도착만으로 취소를 강제하지 않는다. 선택은 참여자가 맥락을 보고 하도록 한다.
생성 중 새 내용을 받을 수 없는 CLI는 현재 응답 이후에 처리한다. CLI별 지원 범위는 먼저 검증한다.
방장의 명시적인 중단·일시정지 명령은 이 선택과 별개로 적용한다.

성격은 말투·적극성·반박 경향·답변 길이의 선호로 전달한다.
고정 지연이나 숫자만으로 자연스러운 대화가 보장된다고 가정하지 않는다.
멘션은 누구에게 말하는지 알려주며, 사용 제한이나 일시정지를 우회하지 않는다.

## 4. 턴·침묵·알림

턴은 누군가의 발화에 다른 누군가가 답한 한 번의 교환이다.
모델 호출이나 답하지 않기로 한 판단을 채팅 턴으로 세지 않는다.

그냥 기다리는 동안에는 모델을 호출하지 않는다.
침묵에서 먼저 말을 꺼내게 하려면 설정한 시간이 지난 뒤 별도 이벤트로 깨운다.
이때도 답하지 않을 수 있다. 전원이 답하지 않으면 같은 침묵을 이유로 계속 호출하지 않는다.
새 메시지나 방장의 재개가 오면 다시 대화에 참여한다.

방장 발언 없이 이어진 대화의 N턴·M턴·K턴을 기준으로 알림과 자동 휴면을 설정한다.
알림은 터미널 → OS → 휴대폰 순으로 확대한다. 기준값은 설정으로 둔다.
휴면·일시정지 중에는 자동 응답과 침묵 깨우기를 멈춘다.

## 5. 사용량과 리밋

- 호출 사용량과 공급자의 구독 잔량을 얻을 수 있으면 표시한다.
- 잔량이 설정한 기준 아래면 추가 입력을 보내지 않고 관전 상태로 둔다.
- 조회 실패는 ‘미확인’으로 표시한다. 잔량이 0이거나 무제한이라고 가정하지 않는다.
- 조회가 안 되더라도 공급자의 제한은 적용된다. 실제 한도 초과가 오면 해당 참여자를 쉬게 한다.
- 한도 초과를 계속 재시도하지 않는다. 리셋 시각을 알면 그 이후, 모르면 방장 확인 후 재개한다.
- 별도로 설정한 참여자 예산과 게스트 소유자의 제한은 조회 실패 때도 해제하지 않는다.

처음부터 복잡한 비용 예약·정산 시스템을 만들지 않는다.
취소된 요청도 보고받은 사용량은 기록한다. 확인되지 않은 사용량은 미확인으로 남긴다.
게스트 데몬은 자체 호출 수·사용량 상한을 적용하며, 방장이 이 정책을 완화할 수 없다.
제한을 지킬 수 없는 게스트 실행은 받지 않는다. CLI별 강제 방법은 실제로 검증한다.

## 6. 기록·맥락·장애

- 공유 기록에는 메시지 ID, 발신자, 답변 대상, 순서를 남긴다. 작성 중 초안과 게시된 메시지를 구분한다.
- 각 세션에는 아직 전달하지 않은 대화를 전달한다. 다른 참여자의 말은 발신자를 붙인 인용 데이터로 다룬다.
- 취소한 초안이 CLI 세션에 남을 수 있으므로, 공유 기록과 어긋났을 때의 재개·세션 재생성 방법을 확인한다.
- JSONL에는 대화, 상태 변경, 확인된 사용량을 기록한다. 재시작으로 이전 모델 호출을 자동 반복하지 않는다.
- 프로세스 종료·응답 지연·사용 제한은 해당 참여자에게만 적용한다. 다른 참여자의 대화는 계속된다.
- 반복 장애가 난 참여자는 관전 상태로 두고 알린다. 복구 시 세션과 미처리 메시지를 확인한다.

## 7. 방장 제어와 외부 연결

방장은 참여자·모델·추론 깊이·성격·예산·소유자·MCP 도구를 설정한다.
운영 중 모델 변경은 다음 실행부터 적용한다. 음소거·강퇴·일시정지·재개를 제공한다.
화면에는 작성 중·관전·사용 제한·휴면 상태를 표시한다.

내 에이전트에는 MCP 도구를 줄 수 있다. 게스트는 도구 없이 대화만 하도록 소유자 쪽에서 제한한다.
방을 MCP 서버로 노출해 외부 클라이언트도 연결한다.
Telegram 답장과 MCP 명령은 접속자의 권한을 확인한 뒤 처리한다.

## 8. 먼저 확인할 것과 진행 순서

1. 두 CLI의 응답 생략, 생성 중 새 입력, 취소·재개, 사용량·리밋 신호를 확인한다.
2. 최소 TUI와 기록·제한 처리를 갖추고 사람 + Claude + Codex가 대화하게 한다.
3. 동시 답변, 작성 중 새 메시지, 전원 침묵, 한도 초과를 확인한다.
4. 실제 대화에서 중복 답변·무한 맞장구·지나친 침묵을 보고 성격과 깨우기 정책을 조정한다.
5. 알림·Telegram·웹·MCP 접속·게스트 연결을 확장한다.

자연스러운 대화 품질과 CLI별 수정·중단 지원은 아직 확인되지 않았다.
이 결과를 보고 세부 정책을 정한다.

- [Usage tracking](https://docs.openclaw.ai/concepts/usage-tracking): 사용량·구독 잔량 조회와 미확인 상태 처리.
